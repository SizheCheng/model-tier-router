# R4: OpenAI Codex App Server host adapter seam

## Status

Source-only reference candidate. It does not start `codex app-server`, send a
JSON-RPC request, launch a model, install a hook, or grant itself authority.

R4 implements the smallest missing seam between the R3 Router experiment
proposal and a Codex host that is entitled to apply automatic per-turn model
selection.

## Why this is the next component

The official App Server lifecycle requires one `initialize` request followed by
an `initialized` notification before other requests. The stable API exposes
picker-visible models through `model/list`, and `turn/start` accepts both
`model` and `effort`.

The official manual also says `clientInfo.name` identifies the integration in
the OpenAI Compliance Logs Platform and that enterprise integrations should
contact OpenAI to be added to a known-clients list.

## Reference API

`MTR_CODEX_APP_SERVER_HOST_ADAPTER_R1` provides four offline operations.

### Stable initialization messages

`build_initialize_request` emits:

- a caller-supplied, validated `clientInfo`;
- `experimentalApi: false`;
- `requestAttestation: true`.

`build_initialized_notification` emits the required handshake notification.
Neither function opens a transport.

### Complete visible model catalog

`build_model_list_request` always requests picker-visible entries with
`includeHidden: false`. `merge_model_list_pages` rejects cursor loops,
duplicates, incomplete final pages, empty catalogs, and more than 256 entries.
The merged response is the catalog input consumed by the R3 proposal builder.

### Host-authenticated capability seam

R4 deliberately does not implement a local production signer, shared secret,
or self-issued JSON authorization. Compilation requires two host-owned
interfaces:

1. `HostCapabilityVerifier.verify(envelope)` authenticates the opaque envelope,
   issuer, and claims outside the Router.
2. `HostNonceConsumer.consume(nonce_sha256, expires_at_utc)` atomically rejects
   replay.

The authenticated claims must bind:

- the R3 proposal, R2 plan, and deterministic assignment;
- App Server protocol and model-catalog digests;
- the selected catalog entry, model, and reasoning effort;
- the intended `clientInfo.name` audience;
- a maximum of one model start and the exact `turn/start` method;
- host catalog, entitlement, assignment, and attestation validation;
- a lifetime no longer than ten minutes.

A claims object cannot authorize approval-policy, sandbox, network, permission,
or write-scope expansion.

### Compile one automatic turn selection

`compile_turn_start_request` accepts the host application's existing
`TurnStartParams`, replaces only `model` and `effort`, and returns:

- an unsent `turn/start` JSON-RPC request;
- a redacted, SHA-256-bound `compiled_not_sent` receipt.

The compiler proves in memory that every non-selection field is unchanged.
This includes `threadId`, `input`, `cwd`, approval policy, sandbox policy,
network setting, personality, service tier, summary, and output schema.

The receipt contains only hashes, selected model/effort, verifier/nonce facts,
and immutable authority/privacy boundaries. It excludes the raw capability,
prompt, thread id, paths, model output, tool output, and error text.

## Causal experiment path

For each eligible turn, the intended host sequence is:

1. initialize the App Server connection and request attestation;
2. enumerate and merge the complete visible model catalog;
3. build the deterministic R3 Router/control proposal;
4. have the Codex host validate entitlement, assignment, policy, and
   attestation, then issue an authenticated one-use capability;
5. compile and send the exact `turn/start` request;
6. reduce `model/rerouted`, `thread/tokenUsage/updated`, and `turn/completed`
   through the R3 outcome component.

The Router/control arm, requested model, resolved model, terminal result,
duration, usage, and reroute chain can then be joined without using
active-model mismatch as a quality metric.

## Exact upstream adoption request

OpenAI integration work is now limited to:

1. register an official `clientInfo.name` for compliance logging;
2. implement `HostCapabilityVerifier` using Codex host identity and
   entitlement;
3. implement atomic nonce consumption in the host;
4. call the compiler immediately before the host sends `turn/start`;
5. associate the redacted launch receipt and R3 outcome with the host's
   experiment assignment;
6. provide enrollment, budget, rollback, administrative policy, and user-facing
   model-selection controls.

The local Router cannot replace any of those host responsibilities.
